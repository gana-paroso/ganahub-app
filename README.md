# GanaHub

개발팀이 함께 보는 프로젝트 정보(공유폴더)와 개발자 개인 도구(IDE 실행, DB 생성, 연결 정보 관리)를 하나로 모은 Windows 11용 데스크톱 앱입니다. Electron 으로 만들었고, 설치 파일(`GanaHub-Setup-<버전>.exe`)로 배포하며 GitHub Releases 를 보고 스스로 업데이트합니다.

## 설치

1. 이 저장소의 **Releases** 에서 최신 `GanaHub-Setup-<버전>.exe` 를 받아 실행합니다. 관리자 권한은 필요 없고(현재 사용자에게만 설치), 설치 위치는 고를 수 있습니다.
2. 설치 파일에 코드 서명이 없어서, 처음 실행할 때 Windows 가 "PC 보호" 창을 띄울 수 있습니다. **추가 정보 → 실행** 을 누르면 설치됩니다. 한 번만 하면 되고, 이후 자동 업데이트에는 나타나지 않습니다.
3. 앱은 켠 뒤 5초 후와 이후 4시간마다 새 버전을 확인합니다. 새 버전이 있으면 백그라운드에서 받고, 화면 맨 위에 **재시작하여 업데이트** 버튼이 나옵니다. 누르지 않고 앱을 닫아도 다음 종료 때 설치됩니다.

## 기능

| 메뉴 | 하는 일 |
|---|---|
| 프로젝트 관리 | 공유폴더의 프로젝트 목록, 즐겨찾기, 도메인 정보와 공통 메모(`config.json`) 조회·수정, 프로젝트 폴더 탐색과 파일명 검색 |
| 연결 관리 | SSH / Git / Jenkins 접속 정보 등록, 연결 테스트, 저장된 비밀번호·토큰 보기·복사 |
| DB 관리 | SSH 로 서버에 접속해 MySQL 의 Database·사용자·권한 조회, 개발용 DB 와 계정 생성(허용 IP 별 권한 부여), 삭제·회수·비밀번호 변경 |
| IDE 관리 | IDE 프로젝트 등록과 실행(Eclipse, VS Code), 개인·공통 메모, Git(원격 확인, Pull, Commit & Push, 태그)과 Jenkins(빌드 이력, 로그, 지금 빌드) |
| 간편접수 | 받은 문의를 업무 포털에 요청업무로 대신 등록 |
| 전역 설정 | 공유폴더 접속 정보, IDE 실행 파일 목록, DB 기본 허용 IP, 업무 포털 연동 |

## 처음 사용할 때

1. **전역 설정 → 공유폴더 연결 설정**: IP, 공유 이름(하위 경로 포함 가능), ID, 비밀번호를 입력하고 연결 테스트를 합니다.
2. **IDE 설정**: Eclipse, VS Code 등의 실행 파일을 이름과 함께 등록합니다. IDE 관리의 등록·수정 화면에서 이 이름으로 고릅니다.
3. **연결 관리**: 쓸 SSH, Git, Jenkins 접속 정보를 등록합니다.
4. (간편접수를 쓸 때) **업무 포털 연동**: 서버 주소, 업무 ID, 공용 키를 입력하고 **연동 규격 파일**을 가져옵니다. 규격 파일은 포털의 접수 규격(주소 형식, 헤더, 필드 이름)을 담은 JSON 이고, 공개 저장소에는 들어 있지 않으니 담당자에게 받습니다.

## 데이터 저장 위치와 보안

- 설정은 개인 PC의 `%APPDATA%\GanaHub\` 에만 저장되며, 공유폴더로 올라가지 않습니다. (공유폴더에 쓰는 것은 프로젝트의 `config.json` 하나뿐이고, 비밀번호·토큰은 들어가지 않습니다.)
  - `global_settings.json`: 공유폴더 접속 정보, IDE 목록, 즐겨찾기, 업무 포털 연동
  - `connections.json`: SSH / Git / Jenkins 연결 정보
  - `ide_projects.json`: IDE 프로젝트와 개인 메모
  - `works_profile.json`: 업무 포털 연동 규격
- 비밀번호·토큰·공용 키는 **Windows DPAPI** 로 암호화해 저장합니다. 현재 Windows 로그인 계정에 묶여 있어, 다른 PC나 다른 계정에서는 풀 수 없습니다. 앱 시작 때 각 파일의 `.bak` 사본을 한 번 만들어 둡니다.
- 연결 관리와 전역 설정의 눈 모양 버튼으로 저장된 값을 볼 수 있습니다. 화면을 공유하는 중에는 열지 마세요.

## 개발

필요한 것: Windows 11, Node.js 22, Git

```powershell
npm install
npm start                # 개발 실행 (자동 업데이트는 꺼져 있음)
npm test                 # 단위·통합 테스트
npm run check:secrets    # 공개 전 검사 (사내 정보·비밀값)
npm run dist             # 설치 파일 빌드 (dist 폴더)
```

- 개발 중 실제 설정을 건드리지 않으려면 환경 변수 `GANAHUB_DATA_DIR` 로 다른 폴더를 지정합니다.
- 화면은 `ui/` 의 HTML·CSS·JS 이고, 메인 프로세스(`main.js`)와 `preload.js` 로 연결됩니다. 기능 코드는 `src/` 에 있습니다.

```
main.js        창 생성, 기능(IPC) 연결, 종료 처리
preload.js     화면에 노출하는 기능(window.api)
src/           crypto(DPAPI) store(설정 파일) settings connections ide projects directory
               share(공유폴더) conntest db git jenkins works updater
ui/            화면 (HTML/CSS/JS, 글꼴 포함)
test/          테스트
scripts/       check-secrets (공개 전 검사)
```

## 새 버전 배포

버전은 **태그 이름이 곧 버전**입니다. `package.json` 의 버전은 관리하지 않고(`0.0.0` 그대로 둡니다), 파일을 고칠 필요도 없습니다. 버전은 `2.0.0` 부터 시작했고(이전 Python 앱이 1.0.x 였고, 이 Electron 앱이 그 뒤를 잇습니다), 이후 `2.0.1`, `2.0.2` … 순서로 올립니다.

1. 변경을 커밋하고 푸시합니다.
2. 새 버전의 태그를 만들어 올립니다. (`v` + 숫자 3개)

   ```powershell
   git tag v2.0.2
   git push origin v2.0.2    # 또는 git push --tags
   ```
3. 태그가 `v2.0.2` 처럼 **v + 숫자 3개** 일 때만 GitHub Actions 의 `release` 가 동작합니다. 사내 정보 검사, 태그에서 버전 정하기, 테스트, 설치 파일 빌드를 한 뒤 Releases 에 **초안(Draft)** 하나를 만듭니다. 설치 파일(`GanaHub-Setup-2.0.2.exe`), `.blockmap`, `latest.yml` 3개가 모두 있어야 합니다. 앱 화면의 버전 배지도 이 태그의 버전으로 표시됩니다.
4. 내용을 확인하고 **Publish release** 를 누르면 그 순간부터 사용자 앱이 새 버전을 받기 시작합니다.

- `v2.0`, `v2.0.2-beta`, `release-1` 처럼 모양이 다른 태그는 아무 일도 일어나지 않습니다. (오류가 아니라 실행되지 않습니다)
- 이미 공개한 버전에 문제가 있으면 같은 버전을 덮어쓰지 말고 더 높은 버전을 새로 냅니다.
- 로컬에서 `npm start` 로 실행하면 버전 배지가 `v0.0.0` 으로 보이고, 로컬에서 `npm run dist` 로 만든 설치 파일도 `0.0.0` 입니다. 배포용 설치 파일은 항상 태그를 올려 GitHub 에서 만듭니다.
- 설치 파일이 서명되지 않아서, Releases 에 올릴 수 있는 GitHub 계정이 곧 모든 사용자 PC에 설치할 수 있는 권한입니다. 소유 계정에 **2단계 인증**을 켜고 쓰기 권한자를 최소로 유지하세요.

## 공개 저장소 원칙

이 저장소는 공개입니다. 사내 정보가 올라가지 않도록 아래를 지킵니다.

- 사내 주소, 계정, 고객사 이름, 업무 포털의 접수 규격은 코드·문서·예시에 쓰지 않습니다. 예시는 `192.168.0.x`, `example` 같은 일반 값을 씁니다.
- 업무 포털 규격은 규격 파일로 분리해 각 PC에만 둡니다. 저장소에 올리지 않는 파일은 `.private/` 에 두며(`.gitignore` 로 제외), 거기에 **금지 목록**(`deny-list.txt`, 한 줄에 정규식 하나)을 두면 `npm run check:secrets` 가 그 목록까지 검사합니다.
- 릴리즈 빌드도 같은 검사를 합니다. 금지 목록을 빌드에서도 쓰려면 저장소 Secret `DENY_LIST` 에 그 파일의 내용을 넣어 둡니다. (없으면 사설 IP, 개인 키, GitHub 토큰 같은 일반 규칙만 검사합니다.)
- 푸시하기 전에 `npm run check:secrets` 를 한 번 실행하세요. 걸린 내용은 로그에 남기지 않고 파일과 줄 번호만 알려 줍니다.
